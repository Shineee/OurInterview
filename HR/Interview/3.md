# 第3页
* 讲一次你经历过的团队冲突，你是怎么处理的？

  > 考察点：沟通方式与大局观。
  >
  > 思路：用 STAR 结构（情境-任务-行动-结果）。冲突本身不扣分，扣分的是"甩锅给同事"。选一个技术分歧类的例子（如方案选型、代码规范），说明你如何对事不对人地摆事实、拉齐目标、必要时找 TL 或数据拍板，最终团队达成一致并说明结果。

* 讲一次你失败或搞砸的经历。

  > 考察点：抗挫能力与反思习惯。
  >
  > 思路：真实地讲一件确实失败过、但你能清晰分析原因的事（线上事故、方案走弯路、项目延期），重点放在"我当时做了什么弥补 + 之后建立了什么机制避免再犯"。例如"那次缓存击穿导致线上报警后，我推动团队补充了限流和熔断的 checklist"。不要讲"我最大的失败是太追求完美"。

* 讲一次你最有成就感的成功经历。

  > 考察点：能力上限与成就动机。
  >
  > 思路：选一个有量化结果的例子，用 STAR 讲清楚：背景有多难、你具体贡献了什么、结果如何（数据）、沉淀了什么。重点是"我"做了什么，而不是"我们"泛泛而谈。可以与技术面项目深挖衔接，保持口径一致。

* 你如何看待工作压力？

  > 考察点：情绪稳定性与压力应对方式。
  >
  > 思路：承认压力存在，说明你的应对机制——拆解任务、排优先级、运动/复盘等具体方法，并举一个高压下交付的例子（如大版本上线前的攻坚）。避免"我完全没有压力"（显得不真实）或大段抱怨压力有多可怕。

* 你怎么处理与上级意见不一致的情况？

  > 考察点：服从性与独立思考的平衡。
  >
  > 思路：先充分理解上级的考量（信息差可能在对方），再用数据和方案充分表达自己的观点；如果仍不一致，执行已定方向并保留观察验证。例如"我在评审会上会把两种方案的风险收益列清楚，如果 TL 拍板，我会全力执行并在复盘时对齐结论"。切忌"我会坚持己见到底"或"一切听领导的"。

* 你的期望薪资结构是怎样的（base / 奖金 / 股票）？

  > 考察点：对整体 package 的理解与优先级。
  >
  > 思路：先了解对方结构再谈偏好。可以说"我更关注总包和成长空间；如果 base 稍低但有明确的奖金/期权机制，我也能接受"。对应届生/初级，可强调成长优先；对资深岗位，可说明对 base 下限的合理预期。谈薪时保持礼貌、给出理由，不卑不亢。
