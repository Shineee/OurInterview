# 第1页
* Activity 正常启动时生命周期方法的调用顺序是什么？从 A 跳转到 B，再从 B 返回 A，两者的回调顺序分别是什么？

  > 正常启动：onCreate -> onStart -> onResume。
  >
  > A 启动 B 时：A.onPause -> B.onCreate -> B.onStart -> B.onResume -> A.onStop（若 A 完全不可见）。部分场景（如 B 为对话框主题、半透明 Activity）A 不会走到 onStop。
  >
  > B 返回 A 时：B.onPause -> A.onRestart -> A.onStart -> A.onResume -> B.onStop -> B.onDestroy。
  >
  > 要点：新 Activity 的 onPause 先于旧 Activity 的 onStop；旧 Activity 恢复走 onRestart 而不是 onCreate。

* 四种启动模式（launchMode）分别是什么？行为上有何区别？

  > standard（默认）：每次启动都创建新实例，可以多个相同实例叠加。
  >
  > singleTop：若目标 Activity 已在栈顶，复用该实例并回调 onNewIntent，不新建；不在栈顶则仍会新建。
  >
  > singleTask：整个任务栈中只有一个实例。启动时若实例已存在，将其之上的其他 Activity 出栈销毁并回调 onNewIntent；常配合 clearOnLaunch 等属性使用。
  >
  > singleInstance：独占一个任务栈，该栈中只有这一个实例，其他 Activity 不能与其共存于同一栈。

* Fragment 与 Activity 的生命周期有什么关系？

  > Fragment 的生命周期依附于宿主 Activity：Activity.onCreate 中会执行 Fragment 的 onAttach、onCreate、onCreateView、onActivityCreated 等。
  >
  > Activity onPause 时 Fragment 才会 onPause；即 Fragment 的生命周期回调整体被"包裹"在宿主 Activity 对应回调之间。
  >
  > 常见顺序：onAttach -> onCreate -> onCreateView -> onActivityCreated -> onStart -> onResume ->（运行中）-> onPause -> onStop -> onDestroyView -> onDestroy -> onDetach。

* Activity、Application、Service 三种 Context 有什么区别？各自适用场景是什么？

  > Application Context：整个应用的单例，生命周期与进程相同，适合与界面无关的操作（注册全局监听、单例持有）；不能 startActivity（需加 NEW_TASK 标志）、不能弹对话框、不能启动/绑定 Service 受限较少但主题无关。
  >
  > Activity Context：有窗口和主题，适合 startActivity、showDialog、LayoutInflater 等 UI 相关操作；生命周期短，持有它容易造成内存泄漏。
  >
  > Service Context：生命周期与 Service 相关，无界面，适合 startService/bindService，但不能直接启动 Activity（需 NEW_TASK）。
  >
  > 选型原则：能用生命周期匹配的短 Context 就不要用 Application Context 持有 Activity 级资源。

* Activity 在横竖屏切换时会发生什么？onSaveInstanceState 何时被调用？

  > 默认情况下（未配置 configChanges），销毁重建：onPause -> onSaveInstanceState -> onStop -> onDestroy -> 重新走 onCreate（ savedInstanceState 非空可恢复数据）。
  >
  > onSaveInstanceState 在 Activity 可能被系统销毁时调用（如按 Home、来电、横竖屏切换），正常用户主动 finish 时不会调用。
  >
  > 若在 manifest 中声明 android:configChanges="orientation|screenSize"，则不重建，回调 onConfigurationChanged。

* Android 中如何保证 Activity 被系统回收后能恢复界面状态？

  > 重写 onSaveInstanceState 保存关键数据（onCreate 的 savedInstanceState 参数或 ViewModel）。
  >
  > ViewModel 横竖屏场景下不随 Activity 销毁，适合持有界面数据；持久化数据用 SharedPreferences / 数据库。
  >
  > 注意：onSaveInstanceState 只适合保存轻量的 UI 状态，不适合保存大数据。
