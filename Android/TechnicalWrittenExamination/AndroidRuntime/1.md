# 第1页
* 进程与线程有什么区别？

  > 进程是资源分配的最小单位，拥有独立的地址空间；线程是 CPU 调度的最小单位，同一进程的线程共享堆和方法区，各自有独立的栈和程序计数器。
  >
  > Android 中每个应用默认运行在自己的 Linux 进程中，进程间默认隔离，通信需要 IPC（主要是 Binder）。

* Dalvik 与 ART 有什么区别？

  > Dalvik：JIT（Just-In-Time）编译，安装时不编译，运行时把热点代码编译成机器码，每次启动都要重新 JIT，整体执行效率偏低。
  >
  > ART：AOT（Ahead-Of-Time）为主，安装/系统空闲时（dex2oat）就把 dex 编译成机器码（.oat），启动和运行更快；同时保留 Profile 引导的混合编译（Android 7.0+），平衡安装速度与性能。
  >
  > Android 5.0 起 ART 取代 Dalvik 成为默认运行时。

* 应用默认的 Java 堆内存大约是多少数量级？

  > 早期 Dalvik 时代设备常见 16MB/24MB；现代 ART 设备通常在 256MB 量级（随设备 largeHeap 与厂商配置变化）。
  >
  > 可在 manifest 中申请 android:largeHeap="true" 翻倍左右，但应优先排查泄漏，而不是靠加大堆。

* 什么是 dex？为什么 Android 不直接用 jar？

  > dex（Dalvik Executable）是把多个 class 文件优化合并后的可执行文件格式，多个类共享字符串池、减少冗余，体积更小，更符合移动端约束。
  >
  > jar 内是独立的 .class，加载时内存开销更大；Android 的运行时（Dalvik/ART）直接加载 dex（打包进 APK 的 classes.dex，多 dex 为 classes2.dex 等）。

* 什么是 ClassLoader 的双亲委派？Android 中的 ClassLoader 层级是什么？

  > 收到加载请求先交给父加载器，父加载器无法加载才由自己尝试，保证核心 API 不被篡改。
  >
  > Android 层级：BootClassLoader（加载核心 framework 类）<- PathClassLoader（加载已安装应用的 dex/apk）<- DexClassLoader（可加载指定路径的 dex/jar/apk，曾用于插件化；现在还有 InMemoryDexClassLoader、DelegateLastClassLoader 等变体）。
  >
  > 加载类时每个 ClassLoader 有对应的 DexPathList，按顺序遍历 dexElements 找到即返回——热修复（Tinker 等）正是利用插 dex 到数组前面实现。

* 应用从点击图标到界面显示的大致流程是什么？

  > Launcher 通过 startActivity 发起（Binder）-> AMS 处理，发现进程不存在 -> 通过 socket 通知 Zygote -> Zygote fork 出应用进程 -> 执行 ActivityThread.main -> 主线程 Looper 准备，attach 到 AMS -> AMS 调度 Application.onCreate、Activity.onCreate/onStart/onResume -> ViewRootImpl 创建、measure/layout/draw -> 界面显示。
