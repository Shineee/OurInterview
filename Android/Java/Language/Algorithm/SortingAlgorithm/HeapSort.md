# Java 堆排序

堆排序利用**二叉堆**这种数据结构做选择排序：先把数组原地建成最大堆，然后反复"堆顶（最大值）与末尾交换、缩小堆范围、下 sift"——每次 O(log n) 地选出剩余元素的最大值。

## 二叉堆回顾

- 逻辑上是**完全二叉树**，用数组下标表示：节点 i 的子节点为 `2i+1`、`2i+2`，父节点为 `(i-1)/2`——**不需要指针**，天然适合数组。
- **最大堆**：每个节点 ≥ 其子节点 → 堆顶是最大值。
- 两个核心操作：
  - **siftDown（下沉）**：某节点比子节点小，与较大子节点交换并继续向下，直到恢复堆性质。O(log n)。
  - **建堆**：从最后一个非叶节点 `n/2 - 1` 开始**倒序**逐个 siftDown。整体 O(n)（数学上可证，不是 O(n log n)）。

## 基本思想

1. `buildMaxHeap`：把无序数组原地建成最大堆。
2. 交换 `a[0]`（堆顶=最大值）与 `a[end]`，`end--`——最大值归位到末尾。
3. 对新的堆顶 `a[0]` 执行 siftDown 恢复堆性质。
4. 重复 2~3 直到堆只剩一个元素 → 整体升序。

## 用 java 实现

```java
public class HeapSort {

    public static void heapSort(int[] a) {
        int n = a.length;
        // 1. 建最大堆：从最后一个非叶节点倒序下沉
        for (int i = n / 2 - 1; i >= 0; i--) {
            siftDown(a, n, i);
        }
        // 2. 逐个把堆顶换到末尾并缩小堆
        for (int end = n - 1; end > 0; end--) {
            swap(a, 0, end);           // 堆顶最大值归位
            siftDown(a, end, 0);       // 对缩小后的堆重新下沉堆顶
        }
    }

    /** 对长度为 size 的堆，从下标 start 开始下沉 */
    private static void siftDown(int[] a, int size, int start) {
        int parent = start;
        int child = 2 * parent + 1;          // 左孩子
        while (child < size) {
            if (child + 1 < size && a[child + 1] > a[child]) {
                child++;                     // 取较大的孩子
            }
            if (a[parent] >= a[child]) {
                break;                       // 已满足堆性质
            }
            swap(a, parent, child);
            parent = child;
            child = 2 * parent + 1;
        }
    }

    private static void swap(int[] a, int x, int y) {
        int t = a[x];
        a[x] = a[y];
        a[y] = t;
    }

    public static void main(String[] args) {
        int[] a = {54, 6, 3, 78, 34, 12, 45, 56, 100};
        heapSort(a);
        for (int v : a) {
            System.out.print(v + " ");        // 3 6 12 34 45 54 56 78 100
        }
    }
}
```

实现要点：

- 建堆循环从 `n/2 - 1` 开始（最后一个有子节点的节点），**递减**到 0。
- `siftDown` 用 `>=` 短路避免无谓交换（保证相等时不下沉，虽不稳定但可少做交换）。
- 每次 swap 后只需对**新堆顶**下沉一次——这是 O(log n) 的主体。

## 复杂度与稳定性

| 情况 | 时间复杂度 | 说明 |
| ---- | ---- | ---- |
| 最好/平均/最坏 | **均为 O(n log n)** | 建堆 O(n) + n 次下沉 O(log n) |
| 空间 | **O(1)** | 原地，仅几个下标变量 |
| 稳定性 | **不稳定** | 堆顶与远端交换会打乱相等元素次序 |

**建堆为什么是 O(n)？** 大部分节点在底层、下沉高度低：对第 h 层节点（高度 h）做 O(h) 下沉，该层有 n/2^(h+1) 个节点，求和 Σ h·n/2^h 收敛于 2n → O(n)。面试能讲到这个量级的直觉即可。

## 选型对比与应用

| | 堆排 | 快排 | 归并 |
| ---- | ---- | ---- | ---- |
| 平均 | O(n log n) | O(n log n) | O(n log n) |
| 最坏 | **O(n log n)** | O(n²) | **O(n log n)** |
| 空间 | **O(1)** | O(log n) | O(n) |
| 稳定 | 否 | 否 | **是** |
| 缓存 | 差（跳跃访问） | 好 | 中 |

- 优点：**最坏 O(n log n) + O(1) 空间**，适合内存紧张、要求最坏保证的场景。
- 缺点：缓存不友好（父/子跳跃访问数组）、常数比快排大、不稳定——**通用排序默认仍选快排（或 TimSort）**。
- 典型应用：
  - **优先队列**（`PriorityQueue` / `Heap`）——堆排序思想的直接延伸。
  - **Top K 问题**：维护大小为 K 的小堆，遍历数据，堆顶比当前元素大则替换——O(n log K)，比全排序 O(n log n) 更省。
  - **求中位数**：大小堆（max-heap + min-heap）双堆维护。
  - **堆调整类问题**：任务调度、带权图 Dijkstra（优先队列松弛）。

**面试追问：为什么说堆排"选择排序"？** → 每轮从堆顶（当前最大值）选择出来放到最终位置，本质是选择排序；与简单选择排序的区别是用堆结构把"找最大"从 O(n) 降到了 O(log n)。

## 【面试追问链】

1. **堆排不稳定的具体例子？** → 如 `[{5,a},{5,b},3]`：第一轮堆顶 5 可能与末尾交换，使相等的 5 之间相对顺序相对输入发生翻转。需要稳定时用 TimSort/归并。
2. **为什么不直接对数组 `Arrays.sort` 而要讲堆排？** → 堆排是理解 `PriorityQueue`、Top K、调度器的基础；且它是"最坏 O(n log n) + O(1) 空间"的唯一常见组合（不用额外空间又不赌数据分布）。
3. **建堆用 siftUp 逐个插入行不行？** → 行，但复杂度变 O(n log n)（n 次插入各 O(log n)）；从非叶节点倒序 siftDown 只有 O(n)——这是"自底向上建堆"与"逐个入堆"的复杂度差异，面试区分点。
4. **`PriorityQueue` 是堆排序吗？** → 不是排序算法，是最小堆（默认）实现的优先队列：`offer/poll` 是 O(log n)，`peek` O(1)，**不提供有序遍历**（迭代顺序是堆数组序，不是排序序）。
5. **Top K 为什么用小堆而不是大堆？** → 小堆的堆顶是"当前 K 个中最小的"：新元素比堆顶大才配进来，逐个淘汰——K 个元素常驻，O(n log K)；用大堆则无法快速淘汰内部元素。
6. **堆排的缓存问题有多大？** → 每次 siftDown 访问 `2i+1/2i+2` 跨步很大，几乎每次都不在同一缓存行，实测常数约为快排的 2 倍左右——所以同样 O(n log n)，工程默认仍是快排/TimSort。
