# 第2页 · 多团队协作治理与技术债务管理

## 一、多团队协作下的代码权限与 Review

### 问题

几十个团队共用一个仓库（monorepo）或多个仓库，如何既并行又不互踩？

### 机制级答案

- **Ownership 显式化**：每个模块/目录有 owner 团队（CODEOWNERS 类机制 + 目录即服务边界）；跨模块改动必须双端确认。没有显式 owner 的公共目录会退化为"谁敢改谁改"。
- **权限分层**：
  - 写权限按模块授予，而非全仓库只读+全员可写；
  - 变更权限按风险分级：core/api、路由表、公共依赖版本 → 保护分支 + 指定 owner 审批；feature 内部 → owner 自治；
  - 发布权限与写权限分离：谁能把开关推全量、谁能发版，是单独的权限面。
- **Review 机制**：契约变更（AIDL/路由/DB schema/序列化协议）要求受影响方 owner 必须过目；Review 指标（时长、驳回原因分类）进团队健康度而不是个人 KPI——把 Review 做成赛马指标会杀死 Review 质量。
- **集成策略**：主干开发 + 特性开关（推荐于持续交付团队）或短分支 + 每日合入；集成失败率与解决时长是拆分是否合理的反馈信号。
- **契约与代码分离**：跨团队接口先冻结契约（proto/接口定义 + 兼容规则），实现并行——与后端 gRPC 契约先行同一思想。

### 【为什么这样设计】

并行的代价是协调，治理的目标不是消灭协调，而是**把协调成本从"每次改动"前移到"契约变更"**：日常 feature 改动零协调，契约变更高成本强评审——成本分布与风险分布对齐。

### 【面试官视角】

- 加分：提到 CODEOWNERS 与保护规则的具体组合；契约兼容的破坏性变更流程（弃用窗口）；把 Review 时长当协作成本指标。
- 减分：只讲"多写文档多开会"；无权限模型，纯靠自觉。

### 【追问链】

1. monorepo 还是多仓库？→ 按原子提交需求与工具链成熟度：强原子变更多仓难做；多仓用版本号与依赖机器人补原子性。讲清 trade-off 即可。
2. 如何防止公共库版本地狱？→ 统一依赖版本目录（version catalog）+ 升级机器人 + 兼容性 CI。

## 二、技术债务管理

### 问题

老板问："你常说有技术债，怎么量化？怎么还？还完怎么不反弹？"

### 机制级答案

- **分类**（决定还法）：
  1. 鲁莽债（明知故犯的捷径：无测试的复制粘贴、写死的开关缺失）——利率高，优先还；
  2. 谨慎债（有意识取舍 + 记录了还款计划）——可排期；
  3. 环境债（平台/依赖过时，无法单方面还）——升级或隔离。
- **度量（能进周报的口径）**：
  - 可测：单测覆盖缺口（关键路径优先）、静态分析问题密度、依赖 CVE 数；
  - 可感：构建时长、线上由"已知债"贡献的缺陷占比（打标签归因）、变更失败率；
  - 可比：每个指标按版本/模块看趋势，不搞一次性大扫除式统计。
- **还款节奏**：
  - 每迭代固定比例（如 20% 容量）给债务，而不是"以后有空"；
  - 大额债务立项化（迁移工程要有里程碑与回滚方案）；
  - 还债必须附带**防反弹机制**：门禁（无测试不合并关键路径）、依赖锁、架构测试、体积/性能 CI（见 Performance 页）。
- **组织保障**：债务有 owner、有利率叙事（用缺陷与交付速度的语言向管理层沟通，而不是用"代码不优雅"）；新债入库要过"是否记录+是否有开关+是否可还"三问。

### 【为什么这样设计】

技术债是**用未来交付速度换当下交付速度**的金融行为：不记账、不定利率、不设 owner 的债会利滚利并表现为某季度突然的"全面重构需求"。工程治理与财务管理同构——现金流（迭代容量）比一次性破产重组（大重构）可持续。

### 【面试官视角：考察度 / 加分 / 减分】

- 考察点：是否把债务讲成可运营指标；防反弹机制是否具体；是否理解"重构冻结需求"的组织成本。
- 加分：给出 20/80 容量模型与门禁例子；用缺陷归因证明"债的利率"。
- 减分："我们每季度重构一次"；只会批判代码风格，无度量无 owner。

### 【追问链】

1. 大重构如何立项才不死？→ 绞杀者迁移 + 双跑对比 + 每阶段可发布；禁止"封网半年出大版本"。
2. 如何处理"不还债也活得好"的团队？→ 把债务指标绑定到缺陷率与变更失败率等业务语言，让利率可见，而不是道德绑架。

## 三、架构师面试答法收束

- 演进题永远给**时间轴**：现在规模 → 触发信号 → 下一形态 → 代价清单。
- 治理题永远给**机制**：owner、权限、门禁、指标——凡"靠人自觉"的方案在面试中默认不及格。
- 技术债永远给**财务模型**：分类、利率、容量、防反弹。
